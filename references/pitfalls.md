# Axure HTML 分析常见坑

## 1. 静态 HTML 不是最终界面

Axure 会把部分文字（例如面包屑中间项“一级菜单 /”）放在运行时脚本里。只 grep `<p><span>` 会漏。

**做法**：用 `render_pages.js` 渲染后的 DOM，读 `rendered/<页面>.json` 的 `breadcrumb` / `textNodes`。

## 2. 面包屑与黑色标题条不是一回事

原型顶部通常有两层：

```text
首页 / 一级菜单 / 当前页             ← 面包屑（y≈89）
页面标题 / 列表名称                  ← 黑色内容标题条（y≈151）
```

**做法**：面包屑取顶部第一条含 `/` 的文本行；黑色标题条只作为页面标题，不参与面包屑。

## 3. “需求说明”是画布外便签

`sticky_4` 块通常位于 `left: 1950px` 之类的画布外坐标，是业务需求说明，不是界面文本。

**做法**：

- `annotations[].offCanvas === true` 的块只用于校验业务规则；
- 不要把注释里的字段/按钮直接写进 UI 结构；
- 注释里的 `<ul><li>` 子项要保留层级，不能压平成一行。

## 4. 侧栏菜单会污染面包屑

Axure 页面把侧栏和内容放在同一个 `#base` 里。侧栏也有“首页”“当前页”等文字，按 y 坐标分组时会被误认为面包屑。

**做法**：

- 检测左侧全高块（`x≈0`、宽 180–320、高 ≥ 视口 70%）作为侧栏；
- 侧栏内文本从 `bands` / `breadcrumb` 中排除；
- 侧栏宽度不要硬编码为 240，按实际检测结果。

## 5. `#base` 的 bounding box 可能是 0×0

Axure 的内容全部绝对定位，`#base` 自身没有布局尺寸。

**做法**：

- 不要用 `#base` 的 `getBoundingClientRect()` 判断画布尺寸；
- 主内容区取最大的非全屏、非侧栏块（如 `u5075`，1600×870）；
- 截图用 viewport screenshot，不要对 `#base` 做 element screenshot。

## 6. 动态面板 / 中继器

`data.js` 里的 dynamicPanel / repeater 可能只保留当前状态，或者没有内联表格数据。

**做法**：

- 交互和状态从 `data.js` 取；
- 表格字段、列顺序以渲染截图 + 需求说明为准；
- 无法确认的字段标“需业务确认”。

## 7. 图片型原型

有的 Axure 页面把整个 UI 做成一张大图（例如 `images/<页面>/u0.png`），DOM 里只有 sticky 注释。

**做法**：

- 基线会标记 `imageBased: true`，并给出背景图路径/尺寸；
- 不要用少量残留 DOM 文本推断界面；
- 加 `--ocr` 运行 OCR（默认 `glance "{image}" --ocr`），或手动用 `vision-tools` 分析截图；
- OCR 只用于补表头、字段、按钮等 UI 文字，业务规则仍以 `annotations` 为准。

## 8. `annotations` 的去重

一个注释块可能被拆成多个 `_text` 容器。优先按父级 `uXXXX` 合并；同一 `id` 只保留一条。

**做法**：以 `id` 为键去重；保留最长/最完整的 `blocks`。
